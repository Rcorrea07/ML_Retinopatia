# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

Binary image classifier for diabetic retinopathy detection (fundus/retina photos) using transfer learning with EfficientNet (Keras/TensorFlow, run on Colab A100). The design choices come from the top Kaggle solutions of the DR 2015 and APTOS 2019 competitions (see `docs/REFERENCIAS.md`). The deployed model must stay light — **one B0-sized network + light TTA, for phones** — and an exam has **both eyes** of the patient; heavy networks (B4) only appear as distillation teachers. The current plan and its results table live in `docs/PLANO_V4.md`.

The project is split in two halves that must stay in their roles:

- `src/retinopatia/` — all the real logic, as importable Python modules. This is what gets edited.
- `notebooks/Retinopatia_0_1.ipynb` — a **thin orchestrator** for Google Colab, the only training notebook. Each code cell is one or two calls into the package. Do not move logic back into the notebook; when a cell would grow beyond a call plus its arguments, the logic belongs in a module. `Preparar_Caches.ipynb` (builds image caches with the user's personal Drive mounted), `Analisar_Resultados.ipynb` (CPU-only comparison of saved predictions) `Treinos_Paralelos.ipynb` (several same-size trainings in one session, see `execucao.py`) `Modelo_Final.ipynb` (R09: the chosen model measured once on the test set and exported to TFLite, see `modelo_final.py`) and `Baixar_Datasets.ipynb` (personal account, CPU: downloads the extra datasets of `docs/DATASETS.md` straight into the Drive `Datasets` folder, `ambiente_colab.baixar_datasets_externos`, Kaggle token from the Colab secret `KAGGLE_API_TOKEN`) follow the same rule.

All code, comments, docstrings, and print output are in Portuguese — preserve that convention when editing, including new module and function names.

## Execution environment

Editing happens locally (VS Code); **execution happens entirely inside Google Colab** because of the GPU.

- There is no local virtualenv, TensorFlow, or CUDA install, and none is wanted. Do not try to `pip install` the dependencies or run the pipeline locally, and do not assume any of the imports (`tensorflow`, `cv2`, `sklearn`, …) resolve on this machine.
- `requirements.txt` is documentation of what Colab provides — not a local install target.
- The code reaches Colab through git: the notebook's first cell clones `https://github.com/Rcorrea07/ML_Retinopatia.git` into `/content/ML_Retinopatia`, fetches and checks out `REVISAO_CODIGO` detached (default `origin/main`; a tag or commit reproduces an old run), and puts its `src/` on `sys.path`. `%autoreload 2` is enabled so re-running that cell picks up pushed edits without restarting the runtime. **Changes only reach Colab once pushed** — mention that when finishing work the user will run there.
- **Experiments are named, one per Colab session.** The notebook's first cell sets `RETINOPATIA_EXPERIMENTO` before importing the package; `experimentos.py` (pure Python) maps each name to the constants it changes, and `configuracao._valor()` applies them before the derived paths are computed. A constant the experiment names but no `_valor()` call reads raises at import (typo guard). To make a constant tunable per experiment, wrap its default in `_valor("NOME", padrao)`. The first cell is a Colab form (`REVISAO_CODIGO`, `EXPERIMENTO`, `SEMENTE`, `FUMACA`, `AVALIAR_TESTE`): open the notebook straight from GitHub in each session and fill it in. There are no per-run notebook copies any more (the R01–R12 copies that actually ran are in tag `v4-original`). Parallel runs: one session of `Treinos_Paralelos.ipynb` (cheaper than several sessions since 28/10): `execucao.rodar_rodada()` processes the images once, runs each (experiment, seed) as its own `python -m retinopatia.execucao` process on the same GPU (as many as `VRAM/RAM_POR_TREINO_GB` allow; TF memory growth on), smoke-tests each first, consolidates and shuts the session down at the end even on error (`ambiente_colab.desligar_ambiente`). An A100 session bills ~6.8 units/h whether the GPU is busy or not; a 768 px training uses ~13 of its 80 GB VRAM and ~25 of 167 GB RAM. The notebook process must not import TensorFlow. The form sets the environment: `FUMACA` → `RETINOPATIA_FUMACA=1` (smoke run: few whole patients, one epoch per phase, `_fumaca` folder, model kept out of `modelos/`), `AVALIAR_TESTE` → `RETINOPATIA_AVALIAR_TESTE=1` (final model only), `SEMENTE` → `RETINOPATIA_SEED_TREINO` (training seed; `SEED_SPLIT` stays 42 so splits never change).
- **Every training is traceable to its code and never overwritten.** `NOME_EXPERIMENTO` = experiment + backbone + size + preprocessing + training seed + `_extra` + `COMMIT_CODIGO` + `ID_EXECUCAO` (date-time fixed at first import and kept in the process environment, so autoreload does not move the folder). `utilitarios.salvar_configuracao()` writes `configuracao.json` (all constants, including `SOBREPOSICOES_EXPERIMENTO`, + commit, uncommitted-changes flag, GPU, TF version) and `codigo_src.zip`. `avaliacao.registrar_experimento()` writes only the run's own `resumo.csv`; `avaliacao.consolidar_experimentos()`, run once after parallel sessions, merges them into `resultados/registro_experimentos.csv` (concurrent writers to one CSV lose rows). Don't pull mid-experiment. Tags: `treino-v2` = `de5cc37`; `campanha-codex-2026-10-20` = the closed E01–E11 campaign (runs used `a6e457a`; not merged into main).
- Each epoch's CSV history also gets the learning rate, peak GPU memory and system RAM (`MonitorRecursos`) — use it to size batch/resolution/backbone instead of guessing.
- Dataset comes from Drive: `/content/drive/MyDrive/Datasets/diabetic-retinopathy-detection.zip` (a share from the user's personal account; `RETINOPATIA_ZIP_DATASET` overrides the path). Extraction, the preprocessed image cache (`/content/dataset_retina_v3_<size>`), and the split CSVs (`/content/drive/MyDrive/ProjetoRetinopatia/dados_internos/splits/{treino,validacao,teste}_v2_seed_42.csv`) are all cached, and each step skips itself or reloads if its output already exists.
- **Image caches of 512 px or more live in the user's personal Drive**, folder `ProjetoRetinopatia_caches`, shared read-only with the project account and reached through a shortcut with the same name in its "Meu Drive" (`PASTA_CACHE_COMPARTILHADA`). The project Drive (15 GB) cannot hold them, and a file written through the shortcut would count against the project quota, so only `Preparar_Caches.ipynb` writes caches (`RETINOPATIA_GRAVAR_CACHE=1`, personal Drive mounted, `fontes.preparar_caches()`). `restaurar_cache_imagens` looks in the shared folder first and then in `dados_internos/cache` (the 448 caches). A training session that finds no cache processes images locally and does not save them. **Caveat:** a Colab session of the project account refuses to mount the personal Drive (`mount failed`), so caches are built in the personal account's free Colab (CPU, 2 cores). On 22/10 it lacked disk for the raw EyePACS extraction; on 30/10 it had 215 GB free (the peak, the 2015 test, needs ~110 GB), and the 768 caches (external datasets first, then train and extras, `Preparar_Caches.ipynb` with `R12_b0_768_externos`) were started there, ~6–8 h. Without a cache, a 768 px session spends ~2 h of A100 processing images. The same Drive account also holds another research project (leprosy/HansenIA): never touch its files.
- Everything that must survive a Colab disconnect lives under `MyDrive/ProjetoRetinopatia/`: `modelos/` (one final `.keras` per run, named `NOME_MODELO` = backbone_size_preprocessing_commit, e.g. `B4_448_v3_1ccd2cb.keras`, plus `_seed<N>` when the training seed is not 42; the v2 model is `B4_448_v2_de5cc37.keras`), `resultados/<NOME_EXPERIMENTO>/` (`CSVLogger` histories, `predicoes_*.csv`, `configuracao.json`, `codigo_src.zip`) plus `registro_experimentos.csv`, `relatorios/` and `notebooks/` (the user's PDFs and executed notebook copies, not written by code), and `dados_internos/` with `splits/` and `cache/` (a zip of the preprocessed images per preprocessing version — when it exists, the notebook restores it and extracts only `trainLabels.csv` instead of the raw dataset). Phase checkpoints (`melhor_modelo_fase*.weights.h5`) stay on the local disk (`/content/checkpoints/`): the final `.keras` already holds the best weights, and on Drive they repeated 100–400 MB per run.

### Local verification

Only static checks are possible locally — the pipeline itself can be verified only by running the notebook in Colab:

```bash
python3 -m py_compile src/retinopatia/*.py
```

Standard-library tests (no TensorFlow) cover experiment resolution, the snapshot of every derived name and path (`tests/retrato_configuracao.json`: run folders, caches and model names that old runs on Drive depend on) and the package rules (no `configuracao` defaults, TF-free parallel notebook). Tests that need numpy/pandas/scikit-learn/OpenCV skip locally and run in the first cell of `Analisar_Resultados.ipynb` on Colab, which also holds the metric regression check (`analise.retrato_metricas` / `conferir_regressao`, CPU only; the `antes` snapshot of 19/11/2026 is never rewritten):

```bash
python3 -m unittest discover -s tests -v
```

There is no linter config or build step.

## Domain logic worth knowing before editing

- **The decision is binary, but the model also learns the 5 grades.** `level` 0–4 is preserved as `level_original` and collapsed into `target`: 0 = no retinopathy, 1 = any grade 1–4. The model has two outputs: `doente` (sigmoid on `target`, BCE — this is the decision) and `grau` (linear regression on `level_original`, Huber loss, weight `PESO_PERDA_GRAU`) as an auxiliary head. Evaluation uses only `doente`.
- **Extra training data (`USAR_DADOS_EXTRA`).** The Kaggle zip has 88,702 images: 35,126 in `train` (the only ones the split uses) and 53,576 in `test`, whose labels are not in the zip — `carregar_dados_extra` downloads `retinopathy_solution.csv` (the organizers' file, same URL TensorFlow Datasets uses) to `MyDrive/Datasets/`. Those images only ever go into training (`ampliar_treino`); validation and test stay the original split so results remain comparable. They are processed into a separate folder/cache (`*_extra`), and the per-row `pasta_processada` column tells `criar_dataset` where each image lives. Experiment and model names get the `_extra` suffix. Raw extraction uses `7z` straight from the `*.zip.00x` parts and deletes them afterwards (the old `cat` join filled the Colab disk).
- **External datasets (`DATASETS_EXTERNOS`, R12).** DDR (12,522), APTOS (3,662), DeepDRiD (931: regular fundus only, accepted quality only, because its grade is per eye and half the photos are rejected) and IDRiD (516, part B) — 17,631 photos, all ICDR 0–4 — also go into training only, through the same path as the extras: `fontes.preparar_dados_adicionais` (one entry point for every train-only source, used by `execucao.preparar_dados`) runs `preparar_fonte` on each `FonteDados`, which loads the table, restores its own cache (`dataset_retina_v3_<size>_<name>.zip`) or extracts just the labeled photos from the zip and processes them (`pre_processar_dataset(coluna_entrada="membro")`; up to `FRACAO_MAXIMA_FALHAS_EXTERNOS` failures are dropped instead of stopping), and `ampliar_treino` appends them with `origem`. Names get `_externos`. Messidor-2 and mBRSET are reserved for external validation and must never enter training (`docs/DATASETS.md`).
- **The split is grouped by patient and has three parts.** `StratifiedGroupKFold` (10 folds) on `patient_id` (parsed from `{id}_{left|right}.jpeg`): fold 0 = test, fold 1 = validation, rest = train. Asserts enforce that no patient crosses sets. Stratification uses the original 5 grades.
- **Validation picks, test measures.** Checkpoints and the decision thresholds are chosen on validation; the test set is only touched by `avaliar_no_teste()`, which stays closed (`AVALIAR_TESTE` False) for experiments and is opened once for the final model. Never tune anything on test.
- **Pixel sizes of the preprocessing scale with the image.** `SIGMA_BEN = 10 × size/448` and `EROSAO_MASCARA = round(3 × size/448)`, so 448 is exactly the v3 recipe and a larger size is the same recipe at higher detail. Cache folders and zips carry the size.
- **Paired-eye model (`MODELO_PARES`).** Each row is still one eye; `adicionar_par` adds the other eye of the same patient (or the eye itself), the pipeline yields `{"olho", "outro_olho"}`, one shared extractor embeds both and the heads see the concatenation. Predictions stay per eye and aligned with the DataFrame, so evaluation and patient aggregation are unchanged; TTA flips both images.
- **Distillation (`DESTILACAO`).** `gerar_alvos_professor` runs the B4 448 extra teacher (`CAMINHO_PROFESSOR`) once on the training images from the 448 caches, without TTA, caches the probabilities in `dados_internos/alvos_professor_*.csv`, and must run before the student is built (it calls `clear_session`, then restores seeds and mixed precision). The `professor` output is the same sigmoid as `doente`; loss = `PESO_ROTULO_REAL`·BCE(label) + (1 − that)·BCE(teacher).
- **Preprocessing is offline on purpose.** `processar_retina` runs once and caches to disk — it is not part of the Keras pipeline, because doing it per epoch cost ~40 min/epoch. Per-image status strings (`processada`, `existente`, `mascara_suspeita`, `erro_leitura`, `mascara_vazia`, `recorte_invalido`, `erro_escrita`) are tallied and the run hard-fails if any image failed or is missing; `mascara_suspeita` (mask covers < `FRACAO_MINIMA_MASCARA` of the expected retina) is saved and listed, not a failure. `pipeline_dados` uses `tf.ensure_shape` so a cache built at another size fails loudly.
- **v2 vs v3 preprocessing.** v3 builds the mask with a fixed low threshold + largest component + convex hull (Otsu failed on dark photos) and computes Ben's local mean only inside the retina (`blur(img·m)/blur(m)`), which removes the bright/dark bands v2 produced where the camera crops the top and bottom of the circle. The v2 options and the diagnostic of the old v2 model were removed in the November 2026 refactor; that code lives in tags `treino-v2` and `v4-original`. Otsu stays only as the v3 fallback for nearly black photos.
- **Background color is coupled to preprocessing.** With Ben normalization the neutral background is gray 128 (`COR_FUNDO`); the outside-retina fill, the circular mask and the rotation/zoom fill of the augmentation must all use it.
- **Augmentation runs inside the model, on the GPU.** It used to run in `tf.data` on the CPU and was the training bottleneck (≈1.2 s/batch in `fit` vs 0.1 s/batch in `predict`). The random layers only act with `training=True`, so `predict`/TTA see clean images. Don't move it back into `tf.data`.
- **No rescale anywhere.** EfficientNet expects raw 0–255 input; `verificar_escala()` asserts `x.max() > 1.0` to catch an accidental normalization.
- **Validation and test pipelines must never shuffle** — predictions are matched to `df_val`/`df_teste` rows by order (labels and `patient_id` come from the DataFrame).
- **BatchNormalization stays frozen during fine-tuning** even though the backbone is unfrozen — the backbone is called with `training=False` and the BN layers get `trainable=False`. Phase 2 also requires the recompile (`compilar_modelo`) after touching `trainable`.
- **Mixed precision** is enabled by `configurar_precisao_mista()` before the model is built. Output layers and `GeM` are forced to float32; augmentation layers are created with `dtype="float32"` so the backbone input stays full-precision 0–255.
- **Learning rate.** Phase 1 is a short head warm-up at a constant LR. Phase 2 uses `CosineDecay` with linear warm-up (`criar_taxa_cosseno`); there is no `ReduceLROnPlateau` (it monitored `val_loss`, which disagreed with the PR-AUC checkpoint monitor, and Keras rejects it with a schedule anyway).
- **Compare experiments on validation only.** The test set is evaluated once, on the chosen final model; the diagnostic comparisons (grade head, patient aggregation) are run on validation.
- **Decision threshold is not 0.5.** It is picked from the ROC curve as the point reaching at least 90% sensitivity with the lowest false positive rate — a medical screening tradeoff. Falls back to 0.5 only if no threshold qualifies. There are two thresholds: per eye and per patient (patient probability = max of the two eyes).
- Class imbalance is handled with `compute_class_weight("balanced")` turned into per-sample weights by `adicionar_pesos_amostra` — Keras `class_weight` does not work with multiple outputs.
- `GeM` is deliberately not registered with `register_keras_serializable` (autoreload would re-register and Keras rejects duplicates); load the saved model with `custom_objects={"GeM": GeM}`.

## Conventions and gotchas

- **Hyperparameters live only in `configuracao.py`; per-experiment changes only in `experimentos.py`.** Don't reintroduce inline literals in modules or notebook cells; add a named constant instead. A function never takes a `configuracao` value as a parameter default (`def f(x=configuracao.X)` freezes it at import, which autoreload and a second experiment in the same process don't undo): the default is `None` and the body reads `configuracao.X` at call time (`_PADRAO` sentinel where `None` already means something). `tests/test_padroes_configuracao.py` enforces it.
- **The training notebook's metadata asks for an A100 with high RAM** (`gpuType`/`machine_shape`). It used to say T4, and the October campaign ran ~5× slower because of it. Keep `fit(verbose=2)`: per-batch progress bars produced 20 MB logs and froze the browser tab.
- **No IPython magics in `.py` files.** `!unzip`/`!cat` were converted to `subprocess.run(..., shell=True, check=True)` in `ambiente_colab.py`; shell escapes only work in notebook cells.
- **Both phases share one evaluation function and one callback factory** (`avaliar_modelo`, `criar_callbacks` + the `criar_callbacks_fase1/2` wrappers) and one compile function (`compilar_modelo`), and the visual inspection shares `processar_retina` with the batch pass. These were duplicated in the original notebook — keep them unified, parameterizing instead of copying.
- In the notebook, `modelo` is the Keras model variable, so the module of the same name is never imported there; `construir_modelo` is imported directly to avoid the shadowing.
- Any change to preprocessing, the split, or the label mapping invalidates the image cache (local and the zip in `cache/`) and the saved split CSVs — bump `VERSAO_PRE_PROCESSAMENTO` / `VERSAO_SPLIT` in `configuracao.py` rather than silently reusing stale caches. The version is part of the cache paths and of `NOME_EXPERIMENTO`.
- `OPERACOES_DETERMINISTICAS` can be turned off if `enable_op_determinism` slows training or raises for a GPU op without a deterministic kernel.
- The original monolithic notebook (pre-refactor, with its run outputs) is preserved in git history at commit `b6d5b32`.
